# Contributing

Everyone is welcome to use and improve these skills. The most useful contributions are **new, verified lessons**: a failure you hit in SolidCraft, what caused it, and a workaround that you checked.

The quickest way is the **New lesson** issue form (Issues, New issue). It asks for exactly the fields below.

## What a good lesson looks like

- The command and parameters involved, the symptom (the exact error text if there is one), and the workaround.
- The SolidCraft version you saw it on.
- A number to check against, such as a volume or bounding box, so the next reader can tell the workaround worked.
- Marked `(UNVERIFIED)` if you have not been able to confirm it.

## Rules

- Write in English.
- Keep each skill focused. Put a lesson in the skill whose topic it belongs to, and add a new skill only when none fits.
- Every skill is a folder `skills/<name>/` with a `SKILL.md` that starts with `name` and `description` frontmatter. The description says WHEN to load the skill.
- No personal data, machine paths or account details.
- Do not add copyrighted drawings, videos, transcripts or solution files. Describe what you learned instead.
- The four official skills (`solidcraft-modeling`, `solidcraft-editing`, `solidcraft-checking`, `solidcraft-mechanisms`) mirror the SolidCraft project. Fix them upstream first, then update the copy here and the commit in `NOTICE`.

## Pull requests

Open an issue or a pull request describing the lesson and how you verified it. Contributions are licensed under Apache-2.0 like the rest of the repository.
